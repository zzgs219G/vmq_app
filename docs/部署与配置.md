# 部署与配置

## 环境变量（服务端）

在 Cloudflare Pages 项目 → Settings → Environment variables 配置。

| 变量名 | 必填 | 说明 |
|---|---|---|
| `ADMIN_PASSWORD` | 是 | 后台登录密码。缺失时 `/api/admin/*` 与后台页面均返回 500 |
| `APP_SECRET` | 是 | 收款推送的 HMAC 密钥。缺失时 `/api/push` 返回 500 |
| `RESEND_EMAIL_API_KEY` | 否 | 卡密邮件备份。不配则跳过发信 |
| `TITLE` | 否 | 站点标题 |

**注意**：代码中已移除所有默认值兜底。`ADMIN_PASSWORD` 或 `APP_SECRET` 缺失时接口会明确失败，而不是回退到某个公开的默认值。这是刻意的——回退会制造「装完就能用、但配置其实是错的」的假象。

## 绑定（服务端）

| 类型 | 绑定名 | 用途 |
|---|---|---|
| KV Namespace | `FAKA_DATA` | 站点配置、分类、商品 JSON |
| D1 Database | `DB` | 订单、库存、系统日志 |

本地开发复制 `wrangler.toml.example` 为 `wrangler.toml` 并填入实际 ID。该文件已被 `.gitignore` 忽略。

## App 端配置

打开 App → 右上角齿轮 → 通讯设置。

| 设置项 | 填什么 | 对应服务端变量 |
|---|---|---|
| API 接收地址 | `https://你的域名/api/push` | — |
| 推送密钥 | 与服务端 `APP_SECRET` 一致 | `APP_SECRET` |
| 后台密码 | 与服务端 `ADMIN_PASSWORD` 一致 | `ADMIN_PASSWORD` |

**必须填到 `/api/push` 这一层**，只填域名会打到网站首页并被 Cloudflare 的 `_redirects` 重写为 `index.html` 返回 200，App 会误判为推送成功。

填完点「测试连接」，它会先 GET 探活、再发一个故意错签名的 POST，通过返回码告诉你卡在哪一层。

## 权限（App 端）

| 权限 | 用途 | 必须 |
|---|---|---|
| 通知使用权（通知监听） | 抓取微信/支付宝收款通知 | 是，否则完全无法工作 |
| 通知权限 | 显示推送结果提示与常驻状态 | 建议 |
| 电池优化白名单 | 防止后台被系统回收 | 强烈建议 |
| 精确闹钟 | 看门狗准时唤醒 | 建议 |
| 自启动 | 开机恢复监听 | 建议 |

国产 ROM（ColorOS / MIUI / HarmonyOS 等）有独立的省电策略，仅靠上述权限不够。App 内「保活设置」会按机型给出具体到设置层级的操作路径。

## 云端构建

GitHub Actions 流水线见 `.github/workflows/build-apk.yml`。

**触发方式**：手动（Actions → 云端打包 APK → Run workflow），或打 `v*` 标签。普通 push 不触发。

**签名**：`release.keystore` 与 `release.properties` 已入库，构建时自动签名，无需配置 Secrets。若要改为 Secrets 注入（更安全），工作流已支持并会优先使用。

**产物**：运行结果页底部 Artifacts，含 APK 与 `checksums.txt`；失败时另有 `error-summary.txt`（精简报错，便于排查）。

## 本地构建

```bash
# 需要 JDK 17+ 与 Android SDK
export ANDROID_HOME=/path/to/android-sdk
./gradlew assembleDebug          # 调试包
./gradlew assembleRelease        # 签名正式包
./gradlew testDebugUnitTest      # 单元测试
```

⚠️ **项目路径不能包含非 ASCII 字符**。Kotlin 编译器会把中文路径编码成 `u514Bu9686...` 形式，导致「源文件全部找不到」。如果工作目录含中文，建议建一个 ASCII 软链接再构建：

```bash
ln -s /path/to/克隆仓库x/vmq_app ~/vmq_build
cd ~/vmq_build && ./gradlew assembleDebug
```

## 部署顺序（首次或改密钥时）

密钥变更会影响所有已装设备，顺序错了会导致支付回调全部失败：

1. 先在服务端配置好 `APP_SECRET` 与 `ADMIN_PASSWORD`
2. 在每台手机 App 里填入对应值，点「测试连接」确认通过
3. 再部署服务端新版本

如果反过来（先改服务端），所有设备会立刻收到 401。
